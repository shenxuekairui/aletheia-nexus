# v0.4.2 Discovery Performance & Evaluation

> Full-text Discovery（全文发现）性能与评价强化说明。

Aletheia Nexus v0.4.2 建立在已经冻结的 v0.4.1 Reliability & Observability Hardening（可靠性与可观测性强化）之上。本阶段不增加新的 Discovery Provider（发现数据源），而是先解决 30 篇真实语料已经明确证明存在的两个问题：串行 Provider 网络等待，以及缺少 Provider 边际贡献的定量评价。

## 1. Evidence from the v0.4.1 baseline

30 篇电解水真实 Benchmark（基准测试）的顺序执行基线：

```text
returned results     30
SUCCESS              30
candidates            98
open access           56
pdf candidates        16

batch elapsed       66.484 s
mean / result        2.216 s
provider work       66.479 s
non-provider         0.004 s
```

该结果说明本地 DOI 标准化、Candidate（候选）构建、去重、排序和 Batch（批处理）逻辑不是当前性能瓶颈；主要耗时来自两个 Provider 顺序等待网络响应。

30 篇语料同时覆盖 AAAS、Wiley、ACS、RSC、Nature Portfolio、Elsevier、Springer、MDPI、Frontiers、IOP、ECS、ECSJ/J-STAGE、AIP、Taylor & Francis、Oxford 等不同出版生态，因此优化依据不是单一出版社的偶然表现。

## 2. Scope

v0.4.2 完成：

- Provider-level Bounded Concurrency（数据源级有限并发）
- 每个 DOI 内 OpenAlex 与 Unpaywall 网络等待重叠
- Batch 仍保持顺序执行
- Provider Contribution（数据源贡献度）评价
- unique/shared canonical route（独有/共享规范路径）统计
- shared-route exclusive metadata（共享路径独有元数据）统计
- provider metadata disagreement（数据源元数据分歧）统计
- Known Resolver Canonicalization（已知解析器规范化）
- DOI legacy resolver 主机统一
- Handle HTTP/HTTPS 统一
- Benchmark 输出并发后的正确 Timing（耗时）语义
- 可选历史 baseline 加速比比较
- 可复现的 30 篇 Benchmark corpus（基准语料）
- 自动行为测试

本阶段刻意不做：

- Batch-level Concurrency（批量级并发）
- 新增 Discovery Provider
- PDF 下载与文件验证
- Landing Page（落地页）HTML 解析
- CARSI / SSO / 浏览器自动化
- Publisher 域名大规模硬编码
- 将 Provider-reported source type 与 observed route type 提前拆成复杂新模型

## 3. Provider-level concurrency

单篇 DOI 仍是一个独立 Discovery 单元，但配置的 Provider 可以同时运行：

```text
DOI
├─ OpenAlex  ─┐
└─ Unpaywall ─┤ bounded provider workers
              ↓
       deterministic result order
              ↓
       merge + ranking
```

当前最大 Provider worker 数固定为 `2`。

这样做的原因：

- 当前只有 OpenAlex + Unpaywall 两个 Provider；
- 真实 Benchmark 证明主要瓶颈是它们的网络等待；
- 不需要引入 `asyncio`（异步 I/O）架构；
- Retry（重试）仍然封装在每个 Provider 内；
- Provider Failure Isolation（数据源失败隔离）保持不变；
- Provider 返回顺序仍固定为 OpenAlex、Unpaywall，不由线程完成顺序决定；
- 未知编程异常仍然显式抛出，不会因为线程执行被吞掉。

Batch 仍逐 DOI 顺序处理。只有 Provider-level 优化经过相同语料实测后，才考虑是否值得引入更高层并发和限流复杂度。

## 4. Timing semantics after concurrency

并发之后不能继续把所有 Provider 的 `elapsed_seconds` 相加后称为“Provider 占 Batch 时间”，因为两个 Provider 的等待时间会重叠。

v0.4.2 Benchmark 改为输出：

```text
provider work sum
    所有 Provider 各自耗时之和；允许大于真实墙钟时间

provider critical path
    每个 DOI 最慢 Provider 的耗时之和；近似 Provider 对墙钟时间的最低约束

provider overlap factor
    provider work sum / provider critical path
    接近 2 表示两个 Provider 大部分时间有效重叠

discovery wall sum
    每篇 DiscoveryResult 的真实墙钟时间之和

coordination estimate
    discovery elapsed - max(provider elapsed) 的保守估计

batch wrapper overhead
    Batch 总墙钟时间减去各 item 墙钟时间之和
```

这样不会因为并发而产生负的“non-provider time”或错误的 190% Provider share（占比）解释。

## 5. Provider contribution evaluation

v0.4.1 的 30 篇数据已经表明，仅统计 `SUCCESS / NO_CANDIDATES` 无法判断 Provider 是否真正提供了新的路径或信息。

v0.4.2 新增 `summarize_provider_contributions()`：

```python
from aletheia_nexus.acquire.discovery import summarize_provider_contributions
```

每个 Provider 统计：

```text
candidate_routes
unique_routes
shared_routes
exclusive_access_type
exclusive_version
exclusive_host_type
exclusive_license
exclusive_source_name
exclusive_is_best
metadata_disagreements
```

### Conservative metadata rule

对于一个由多个 Provider 共同发现的 canonical route（规范路径）：

- 只有某字段**恰好一个 Provider 提供有效值**时，才记为该 Provider 的 exclusive metadata contribution（独有元数据贡献）；
- 多个 Provider 给出相同有效值，不算独有贡献；
- 多个 Provider 给出不同有效值，只记录 disagreement（分歧）；
- 不自动决定哪个 Provider 更权威。

这使 Provider 评价关注真实边际价值，而不是把重复信息重复计功。

## 6. Resolver canonicalization

30 篇语料真实出现了：

```text
http://hdl.handle.net/21.11116/...
https://hdl.handle.net/21.11116/...
```

它们代表相同 Handle persistent identifier（Handle 持久标识符），但 v0.4.1 会因为 scheme（协议）不同而保留两个 Candidate。

v0.4.2 只对已经有证据支持的 persistent resolver（持久解析器）做更强规范化：

```text
http://hdl.handle.net/...  → https://hdl.handle.net/...
http://doi.org/...         → https://doi.org/...
https://dx.doi.org/...     → https://doi.org/...
https://www.doi.org/...    → https://doi.org/...
```

普通网站仍保留原有 HTTP/HTTPS，不进行全局强制升级。

## 8. Acceptance criteria

v0.4.2 冻结要求：

```text

→ OpenAlex / Unpaywall 能证明真实重叠执行

Determinism
→ Provider 结果顺序不受线程完成顺序影响

Failure semantics
→ 一个 Provider 失败不拖垮另一个 Provider
→ Retry 规则保持不变

→ 已知 DOI / Handle resolver 等价 URL 能稳定合并

→ 30 篇 corpus 可重复运行

CI
→ Python 3.11 / 3.14

→ pytest
全部通过
```

## 9. Provider expansion decision rule

v0.4.2 不因为“还有 API 可以接”就新增 Provider。

新增数据源必须至少满足一个真实证据：

1. 在跨领域 Benchmark 中稳定提供 OpenAlex + Unpaywall 都没有的全文路径；
2. 显著改善目前无法获取的论文类型，例如特定学科仓储或预印本；
3. 提供 Acquisition（获取）真正需要且现有 Provider 长期缺失的结构化信息；
4. 新增覆盖收益明显高于认证、限流、维护与失败模式带来的复杂度。

如果当前主要缺口是“Provider 已找到 Landing Page，但没有直接 PDF”，则优先进入 v0.5 Landing Page Resolution / Acquisition（落地页解析/获取），而不是继续堆叠 Metadata/Discovery API。
