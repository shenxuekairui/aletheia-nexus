# v0.4.2 Discovery Provider Assessment

> 是否需要继续增加全文发现数据源的阶段性判断。

## 1. Current evidence

v0.4.1 的 30 篇电解水跨出版社真实 Benchmark（基准测试）得到：

```text
30 / 30 Discovery SUCCESS
98 merged candidates
56 open-access candidates
16 provider-reported PDF candidates

OpenAlex
30 / 30 SUCCESS

Unpaywall
20 SUCCESS
10 NO_CANDIDATES
```

合并后的 98 条 canonical route（规范路径）中：

```text
OpenAlex only          42
OpenAlex + Unpaywall   56
Unpaywall only          0
```

因此，在当前这一组化学/能源领域跨出版社样本上，OpenAlex 已参与全部最终路径；Unpaywall 没有贡献独有 URL，但仍可能贡献 OA、license、version、best-location 等元数据。v0.4.2 新增 Provider Contribution（数据源贡献度）统计，就是为了在并发版本重跑后定量验证这些元数据边际价值。

该结论不能直接外推到所有学科，因此不应据此删除 Unpaywall，也不应据此宣称 OpenAlex 在所有领域覆盖充分。

## 2. The practical gaps are not primarily provider-count gaps

当前真实语料已经出现以下案例：

- J-STAGE 论文存在直接 PDF，但现有 Provider 主要给出 DOI / DOAJ 路径；
- MDPI 论文存在直接 PDF，但个别记录只发现 DOI landing page；
- IOP / Materials Futures 的页面存在 PDF，但 Provider 不一定返回 PDF URL；
- repository candidate 可能最终只暴露 Supporting Information（补充材料），而不一定是正文。

这些案例共同说明：

```text
Known landing / repository route
≠
No full text exists
```

更常见的问题是：

```text
Discovery 已发现入口
↓
但还没有实际访问入口
↓
还没有解析页面中的 PDF
↓
还没有下载并验证正文身份
```

这属于 v0.5 Acquisition + Validation（获取与验证）的核心职责。继续堆叠元数据/发现 API 不一定能解决这个真实缺口。

## 3. Candidate providers

### Crossref

官方 REST API 无需注册即可公开访问，并且部分记录的 `link` 元数据包含 full-text URL、content type、version 或用途信息。

但 Crossref 官方明确说明：

- Crossref 本身主要收集 metadata（元数据），不是全文仓储；
- full-text link 的存在不保证用户实际具有访问权限；
- 链接可能需要订阅、登录或遵循 TDM（文本与数据挖掘）许可。

项目已经在 Metadata（元数据）层使用 Crossref，因此未来可以低成本评估是否复用其 `link` 字段作为 publisher/TDM fallback（出版社/TDM 后备路径）。

**阶段判断：DEFER（暂缓作为核心 Discovery Provider）。**

理由：当前最明显缺口是 landing page → file，而不是完全不知道 publisher route；Crossref link 更适合作为后备补充，而不是现在增加一次默认网络调用。

Official references:
- https://www.crossref.org/documentation/retrieve-metadata/text-and-data-mining/
- https://www.crossref.org/documentation/retrieve-metadata/rest-api/

### Semantic Scholar

Semantic Scholar Academic Graph API（语义学术图谱 API）支持按 DOI 查询 Paper，并可返回 `isOpenAccess` 与 `openAccessPdf` 字段；官方 API 覆盖跨学科论文，并支持 batch endpoint（批量端点）。

它是当前最值得进一步 benchmark（基准测试）的广域候选 Provider，因为它可能直接补充 OA PDF URL。

但它也有明显工程成本：

- 与 OpenAlex / Unpaywall 很可能高度重叠；
- 未认证公共请求共享限流；
- 官方建议使用 API key；个人 key 的初始速率为 1 request/s；
- 若加入默认 per-DOI path，会增加请求量和调度复杂度。

**阶段判断：BENCHMARK-FIRST（先测，不直接集成）。**

建议以后建立一个 `gap corpus`（缺口语料）：只选 OpenAlex + Unpaywall 没有直接有效路径或 PDF 的案例，对 Semantic Scholar 做离线对比。如果它在 gap cases（缺口案例）中稳定贡献明显比例的独有可用 URL，再加入为 optional/fallback provider（可选/后备数据源）。

Official references:
- https://api.semanticscholar.org/api-docs/
- https://www.semanticscholar.org/product/api

### CORE

CORE 是面向开放获取仓储的聚合基础设施，支持按 DOI / title 等方式查询，并聚合 repository / journal full text（仓储/期刊全文）。从能力定位看，它非常适合补充 institutional repository（机构仓储）路径。

但其主要价值与 OpenAlex 当前返回的大量 repository location 存在潜在重叠，而且 API key、速率控制和额外 Provider 维护都会增加复杂度。

**阶段判断：FALLBACK CANDIDATE（后备候选）。**

如果未来跨领域 gap corpus 显示“机构仓储缺失”是稳定失败模式，再专门 benchmark CORE，而不是对全部 DOI 默认调用。

Official references:
- https://core.ac.uk/services/api
- https://support.core.ac.uk/support/solutions/articles/80000945283-harvesting-guidelines

### Europe PMC

Europe PMC REST API（欧洲 PubMed Central 接口）覆盖超过 3300 万出版物，并提供大量全文与开放获取内容，尤其适合生命科学、生物医学和 PubMed/PMC 生态。

当前 30 篇化学/能源语料已经通过 OpenAlex 得到了多个 PubMed / PMC 路径，因此在当前领域没有证据证明 Europe PMC 会带来足够高的独有收益。

**阶段判断：DOMAIN-SPECIFIC OPTIONAL（领域特定可选）。**

如果 AN 以后扩展到生物医学、药物、生命科学工作流，Europe PMC 值得作为专门领域 Provider 重新评估。

Official reference:
- https://europepmc.org/RestfulWebService

## 4. Decision

### v0.4.2 不新增核心 Provider

当前证据不支持为了增加 API 数量而扩展 Discovery Provider。

原因按优先级排序：

1. **当前工程瓶颈不是覆盖率崩溃。** 30 篇跨出版社样本全部完成 Discovery，OpenAlex 已参与全部最终 canonical route。
2. **主要实际缺口是 route → file。** 已知 J-STAGE、MDPI、IOP 案例表明页面有 PDF，但 Provider 不一定直接返回 PDF URL。
3. **Unpaywall 的边际 URL 贡献已经很低。** 在当前样本中无独有 canonical URL，因此新增第三个 broad graph API（广域学术图谱接口）更应该先 benchmark，而不是默认调用。
4. **每个新 Provider 都不是免费的。** 它带来认证、限流、Retry、字段映射、语义冲突、测试和长期维护成本。
5. **v0.5 能解决更靠近用户价值的问题。** 实际下载、Landing Page Resolution（落地页解析）、PDF Validation（PDF 验证）和 Identity Validation（论文身份验证）将直接提高“最终拿到正确正文”的成功率。

## 5. Evidence threshold for adding a provider later

未来新增 Provider 建议满足以下至少一项，并通过真实 gap corpus 验证：

```text
A. unique usable route gain
   在现有 Provider 失败/不足的论文中，稳定贡献独有可用路径

B. direct-file gain
   稳定补充当前体系缺失的可直接获取 PDF / full-text URL

C. domain-specific gain
   在明确学科中显著优于通用 Provider

D. acquisition-critical metadata
   提供现有体系缺失、且 v0.5 获取决策真正需要的信息
```

建议判定方式不是固定写死一个百分比，而是比较：

```text
新增成功论文数
+
独有高质量路径数
+
关键元数据增益

vs

额外请求延迟
+ 限流/认证成本
+ 字段冲突
+ 长期维护成本
```

## 6. Recommended next step

完成 v0.4.2 的并发真实网络复测后，如果：

- 30 篇结果内容基本保持一致；
- Provider concurrency 显著降低总耗时；
- contribution metrics 能稳定说明 OpenAlex / Unpaywall 的边际价值；

则 Discovery Core 可以阶段性冻结。

下一阶段优先进入：

```text
v0.5.0 Direct Acquisition
直接文件获取
↓
v0.5.1 PDF Validation
PDF 验证
↓
v0.5.2 Landing Page Resolution
落地页解析
```

而不是优先增加新的广域 Discovery Provider。

## 7. Final v0.4.2 provider evidence

v0.4.2 使用相同 30 篇 corpus 完成并发真实网络复测后，最终得到：

```text
OpenAlex
  candidate routes          97
  unique routes             41
  shared routes             56
  exclusive metadata        56
    source_name             56
  metadata disagreements     7

Unpaywall
  candidate routes          56
  unique routes              0
  shared routes             56
  exclusive metadata         0
  metadata disagreements     7
```

同时：

```text
30 / 30 works with candidates
20 / 30 works with OA candidate
15 / 30 works with PDF candidate
24 / 30 works with non-resolver route
17 / 30 works with publisher/repository route
```

相对于 v0.4.1 的 98 merged candidates，v0.4.2 为 97；减少的 1 条来自已知 Handle HTTP/HTTPS 等价路径的正确合并，不是覆盖下降。

### Interpretation

这一结果进一步强化了“不新增第三个默认 Provider”的判断：

- 在当前 chemistry/energy corpus（化学/能源语料）中，OpenAlex 已覆盖全部 97 条最终 canonical route；
- Unpaywall 仍没有独有 route；
- 按当前保守统计规则，Unpaywall 也没有独有 metadata contribution；
- 7 处 shared-route metadata disagreement 被保留为分歧，没有自动判定哪个 Provider 更正确；
- OpenAlex 独有的 56 个 `source_name` 贡献说明 Provider 价值不能只看 URL 数量，但当前没有证据显示第三个 broad provider 会解决现有主要缺口。

这仍然只是单领域、30 篇规模的证据，因此**不足以删除 Unpaywall**，也不能宣称 OpenAlex 在所有学科都足够。更合理的下一步是：

1. 进入 v0.5，解决已知 route → file 的真实获取问题；
2. 后续建立跨领域 `gap corpus`；
3. 优先对 Semantic Scholar 做 benchmark-first 评价；
4. 只有出现稳定独有覆盖收益时，才新增 optional/fallback provider。

### Final decision

**v0.4.2 不新增核心 Discovery Provider。**

Discovery Core 在当前阶段可以冻结，Provider expansion（数据源扩展）转为 evidence-driven fallback strategy（证据驱动的后备策略），而不是默认堆叠更多 API。

> 注：本节的“final decision”是指 v0.4.2 阶段的架构决策；未来跨领域 gap corpus 若出现新的稳定失败模式，可以重新打开 Provider expansion 评估，但不回溯修改已经冻结的 v0.4.2 语义。

**Status: FROZEN FOR REVIEW.**
