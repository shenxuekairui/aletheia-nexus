## 实际实现

- 一个真实 DeepSeek Responses Provider：文本/选页图像、JSON 约束、本地再次校验、
  限时/有限网络重试、鉴权/权限/额度/网络/格式/截断分类、用量与估算费用。
- 同一 JSON Task 支持 organize/extract/procedure/compare、自定义字段/类型/单位/阶段。
- Task Package 引用 v0.7 规范工件、原 PDF 哈希、选页/块、表格观测、SI、备注和
  人工覆盖层。有限补页生成子包；原文件只读。direct 可只提供已登记的原 PDF。
- 批量逐文献检查点、部分失败隔离、缓存和恢复、一次有诊断的输出修正。
  相同输入的有效结果复用；缓存不会把部分结果标为完整成功。
- 带来源的结构化记录、按步骤的过程整理、跨文献汇总、Markdown/CSV/JSONL、
  运行清单、离线导出和带历史的人工修订。AI 响应中没有人工确认字段。
- 任务可选择 export_formats，离线导出可覆盖格式；独立主张另存 claims.jsonl。
  记录和跨文献主张均可人工修订，改写可撤销被修改对象的人工确认。
- 本地模式零远程调用，输出选定原文材料；没有 API Key 时旧本地功能正常可用。

模块职责见 [设计](V08_DESIGN.md)，命令及密钥配置见 [使用指南](V08_USER_GUIDE.md)。
新增评测脚本仅作运行/评分辅助，没有引入数据库、模型路由、Agent 框架或 GUI。

### 原页抽查与错误

对 C 在运行前冻结了 11 个原子检查项（同一制备记录），由助手查看原 PDF 第6–7页。
它不是人类专家标准。三个模式的组分/数值和两项“未报告”判断正确，但都把配液字段
的 step_ids 同时关联到前面的基底准备或清洗步骤，4 个原子项因此按关联要求判错。
关联计入正确性时，三个模式在此小检查集均为查准率 5/9、查全率 5/9、完整记录
0/1；不能把这组比例当作系统总体成绩。逐项判断在 C-*.review.json，评分分母冻结于
C-source-review-plan.json。提示词 v5 已针对这个问题修改，后续验证另行记录。

随后按同一任务、同一固定检查项执行 v5：三个模式的配液关联都修正到配液/暴露步骤，
11 项检查均符合该小样本参考，保留了“可检查”的语气和制备参比/时间未报告的判断。
每种模式修复了上述 4 项关联错误；固定检查内未发现新错。记录在 `focused-v5/`。
这不表示整条记录或所有生成语句均正确：direct 将原文 exposed 写成更具体的“浸入”，
该操作细节未在原句明确报告，是固定分母以外的新待核对项。不能用 11 项通过掩盖它。

另外观察到：原页引用有时只摘录表注，未摘录包含数值的行；混合路径仍会选到错误
的文本块；模型会误称本批其他论文缺失，或把未使用解析器误标为 parser_problem。
这些是模型质量问题，不由通过 JSON Schema 自动消除。正式验收还需逐主张支持检查。
