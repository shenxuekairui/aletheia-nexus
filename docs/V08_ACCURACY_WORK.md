# v0.8 自动提取准确率改进记录

2026-10-26 起继续开发，目标是在不依赖 GPT 修订输出的运行链路中达到字段查准率
90% 以上，同时单独测量召回率、完整记录正确率和证据支持率。目标尚未达成。
这里的 GPT 仅用于开发与独立评测，参考答案是助手参考，不能称为人工专家标准。
开发集表现也不能代替新留出集验收。历史发布与评测分母保持不变。

## 新增机制与设计取舍

- 两个 DeepSeek 角色执行有限的提取—复核—修订流程。复用现有 Provider、任务、来源
  校验、预算、导出及本地缓存，不增加自主 Agent 调度器。复核覆盖每个字段（含空值）、
  步骤、主张及任务覆盖，意见仍是可错的派生数据。
- evidence-review/1 的整体复核容易附和候选；high/24,000 出现输出截断。
  evidence-review/2 因此按少量目标分组，隐藏其他字段的旧答案，保留完整原文材料。
  结构错误可有限修复；后续 evidence-review/3 根据实际失败减少引文格式与编号检查，
  优先复核科学内容、遗漏和条件关联。真实来源/输入页仍需有效。
- 复核失败保留上个有效候选，标明部分完成并禁止把失败复核当作成功缓存。
  成功缓存校验复核前后指纹与派生链，原始 PDF 和解析工件不变。
- 可选 page_and_tiles 使用原有 Poppler 渲染，概览加四个重叠区域。没有新增 Pillow
  或 OCR 依赖。任务材料包仍为 v1，builder 升为 4 以隔离新材料配置与缓存。
  旧包与旧结果继续可验证、导出。
- 根据用户要求，默认配置与示例改为所有角色 high、65,536 输出 tokens、300 秒超时。
  显式历史任务不重写；更高思考预算是否提高效果必须重新测量。
