## 修复映射

| 观察到的故障 | 原因/证据 | 代码修复与验收 |
| --- | --- | --- |
| 验证后已结束的条目不恢复 | 零等待调用结束后仅留页面；同一批次后续处理不会复查已清除的挑战 | BrowserSession 保存当前 DOI 的待处理页面；批次结束复查已经清除且返回原出版社的挑战一次；仍未清除的不盲重试；检查点记录 ACCESS_CHECK 恢复阶段及状态历史 |

| TF 已识别机构却再次选机构 | 目标正文仍 needAccess=true，通用机构提示被当成新认证 | 只在文章 DOI 元数据匹配、机构已识别、同 DOI 正文链接明确受限且购买选项存在时归类权限边界；不硬编码机构名称；验证码保留优先级 |

| 已下载的 Elsevier 被报失败 | 文本提取字体异常覆盖整个获取结果；汇总混用最新失败和历史成功 | 独立 audit_verified_pdf：完整性与可选文字审计分开；文字异常只作 warning；新回归 runner 将审计放在获取异常处理之外，单列 latest_attempt / best_verified / attempt_history |

所有成功仍由共享 PDF 结构、目标身份与 ARTICLE 角色校验决定。附件不会计为正文成功。

## 行为边界

- 默认交互模式仍在调用内等待用户完成正常登录/MFA/验证码，然后继续。
- 有限等待超时后，批次只在确实观察到挑战清除时进行一次自动回访。
- `--non-interactive` 不等待用户，也不启动后台监视。命令退出后不会仍然下载；下次运行通过检查点和当前浏览器重新恢复。
- `--stop-on-interaction` 继续保持在未解决交互处停止整批的语义。
- 本次没有增加跨设备认证迁移、机构订阅黑名单或后台常驻服务。
- 外部浏览器的认证与网络条件会变化，新的验证码要求不等于修复失败或没有订阅。

## 回归方法

确定性测试检查响应未完成时不读取、旧 viewer 后备恢复、官方 PII 入口、状态历史、审计字体告警和脱敏。
真实 Chromium 夹具检查不同示例机构的 Wiley remembered-access 激活与第二篇复用、TF 同 DOI 限权与其他 DOI 不误判、无限 fetch/流体读取及大小限制，以及用户完成验证后恢复原页面。
夹具使用自编 HTML 和合成 PDF，既不携带真实凭据，也不把模拟机构当作跨机构订阅证据。

真实官网回归使用本轮已经取得过官网正文的八篇，覆盖 Wiley、Science、Elsevier、RSC、ACS。
TF 三篇与 Thieme 两篇已确认的权限受限条目不重新认证。
原始报告及有版权正文留在仓库外本地测试目录；独立报告不能与此前累计 25/30 混成同一次自动成功率。

可运行：

```powershell
python scripts/retest_publisher_browser.py papers.json `
  --output-dir downloads/publisher-check `
  --cdp-endpoint http://127.0.0.1:9222 `
  --profile my-institution `
  --interaction-timeout 180
```

manifest 为 DOI/title 行列表，入口来自 `url`、Crossref `resource.primary.URL` 或 DOI resolver。
若附加已启动 CDP，实际机构会话由该浏览器决定，单改 profile 名不会切换机构。
同输出目录会保留每次尝试；获取与审计的结果分别记录，历史成功不会被新失败抹去。

## 2026-10-10：Wiley 循环验证与登录被打断

这轮现场问题包含两个不同层次，不能将它们合并成一个“验证码问题”：

- 普通可见浏览器（既有 CDP 接管模式）、Chrome 155、原 AN profile 和直连网络的对照中，用户完成了 Wiley 验证码；随后仍需要正常机构认证。这证明本次对照可通过验证，不证明某个启动参数是验证码循环的唯一原因，也不保证今后不再出现验证码。未使用指纹伪装、验证码破解、代理切换或复制认证 cookie。
- AN 确实存在提前结束机构认证并清理任务标签页的缺陷：只在点击入口后判断一次外部认证域，漏掉稍后从出版社机构选择页跳往 IdP 的情况；PDF 控件进入认证的路径也缺少返回目标约束。另一个竞态是 DOM 读取过程中已经跳到 IdP，却仍使用读取前的出版社域名判断完成。

Git 核对显示，入口后单次判断的逻辑已存在于最早公开快照 `f9a29d8`，不是本轮 CNKI DOI 分流新增。历史成功使用另一独立浏览器 profile，且成功记录证明的是已授权 viewer 交付；不能据此推断该次经过了相同的首次/重新机构登录分支。

修复让整个机构选择过程持续跟踪返回目的地，并为 PDF 入口及弹窗补上认证返回约束。读取前后 URL 必须一致，返回页需要连续稳定确认；没有已识别登录文字的外部 IdP 页面不再代表认证完成。未完成的密码登录、MFA、验证码和浏览器检查弹窗均保留。已记住的机构访问仍可在非交互模式下自动激活：只短暂确认已经清除的页面，不因此等待新的人工登录。已交付且经原身份通道验证的正文仍可结束等待；正常 PDF CDN 跳转不因为跨域就被误当成认证。

## 2026-10-10：PNAS 官网复现、零字节收尾与启动模式对照

本轮不把前述 PMC 成功当成 PNAS 官网验收。只提供 `https://www.pnas.org/doi/pdf/10.1073/pnas.2423542122` 一个来源，关闭其他来源路由，实际新增下载了 10 页正文，原 `pdf_front_matter/v2` 给出 DOI 匹配、首页标题相似度 1.0、ARTICLE。独立文件哈希、获取记录和身份审计通过：

- 首次官网复现 4.38 秒，复用既有认证，通过浏览器 viewer 取回正文。
- 专用浏览器重启后的复测 20.37 秒，历史中实际出现 BOT_CHALLENGE/CAPTCHA，随后 NONE 并取得官网 PDF；这次没有再次卡在无 `.pdf` 后缀、空 DOM 的 PDF 页。不能把分类器的状态历史等同于证明挑战由程序自动解答。
- 最终源码串行复核 3.90 秒，已有会话的官网直接 PDF 请求成功；没有改用 PMC、旧文件或宽松身份门槛。

### 本轮下载收尾

1. 原生捕获已启用时，只有对应 URL 的完成文件才能进入保存；超时、取消或 URL 不匹配不会退回 Playwright 的空占位文件。初始导航的捕获与暂存文件保留到当前路由结束，PDF 控件点击前重新设置捕获，避免 viewer 的临时下载设置影响后续控件。
2. 同一捕获跟踪多个下载 GUID，按所属下载 URL 选择，避免另一个标签页先开始下载就遮住目标。完成路径必须在本次暂存目录内且非空，不接受 `.crdownload`、`.part`、`.tmp`，不再从目录中猜唯一文件。
3. CDP 能力缺失时保留标准下载兼容通道，但空文件明确记为传输失败 `EmptyBrowserDownload`，不进入论文身份校验。空浏览器响应单独记为 `EmptyBrowserResponse`。CNKI 空占位文件进入已有的有限浏览器会话恢复流程；未完成原生下载不再遮住已完整收到的 PDF 响应。
4. 收紧校验后的第一次真实浏览器回归暴露了非默认上下文缺陷：未传 `browserContextId` 时下载设置作用于默认上下文，文件留在另一个目录。已按目标上下文设置及恢复下载行为，保留严格路径校验，没有通过重新接受外部文件来掩盖问题。

以上关闭的是已复现的空占位文件和不完整下载被当作论文校验的路径，不保证服务器永远不会断流。结构、正文角色、DOI/书目身份及 SHA-256 校验仍然必经。

### 验证码与浏览器配置：结果不支持“换参数即可永久根治”

固定 Chrome 155、同一 AN 专用 profile 和直连网络，对照普通启动后 CDP 接管与 Playwright 托管启动；未清理认证、复制 cookies、切换代理或修改指纹。普通模式先成功（7.93 秒）；托管模式重启后出现 SSO 和浏览器检查，等待用户完成机构登录后也取得官网正文（79.39 秒）。这说明托管模式并非必然陷入验证循环，也不能把浏览器重启引起的会话变化排除在原因之外。

恢复普通模式后的后续 Wiley 测试分别出现 `NO_FILE_CANDIDATES` 和独立串行复测的导航超时（45.65 秒），均保留为失败。前一次与 PNAS 复测短暂共用浏览器，存在下载/响应监听相互干扰的混杂因素，不能用于归因启动参数；最终 PNAS 官网验收是单任务串行复核。普通模式不是保证成功的“修复开关”。

源码核对发现托管启动带有 Playwright 默认参数，并拦截上下文请求；普通接管不会安装该上下文拦截。[Playwright 文档](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route)说明路由拦截会关闭 HTTP 缓存。这是已确认的模式差异，但本轮没有证据证明它单独造成循环，因此未删除 URL 安全防护或批量修改浏览器默认参数。[Cloudflare 排障文档](https://developers.cloudflare.com/cloudflare-challenges/troubleshooting/challenge-solve-issues/)也列出浏览器、网络和检测错误等多种可能原因。

当前结论：PNAS 官网获取及已复现零字节缺陷已修复验证；验证码循环的唯一根因仍未确定，不宣称彻底根治。保留直连、独立 profile、浏览器会话复用和人工验证期间不跳转/不刷新页面的行为。本轮未提交、推送或发布。

用户未确认无权限的项目是 Nature Water 的 *Curvature-induced ion docking effect in capacitive deionization*（`10.1038/s44221-024-00340-4`）。此前只是页面购买提示导致 `ENTITLEMENT_REQUIRED`，不是用户确认无订阅，也不是已核验机构授权失败；与已明确确认的 Thieme、ASCE 分开记录。

本轮最终常规回归 **1245 passed、79 skipped**；显式开启真实 Chromium 夹具后，通用获取 **62 passed**、CNKI **16 passed**。78 个浏览器场景单独执行通过，另一个跳过项为外部 OCR 依赖。首次收紧下载路径时的 **10 failed、68 passed** 没有算作验收，按上下文修复后重新执行通过。Ruff、修改文件格式检查及 diff 空白检查通过。上述浏览器夹具是隔离页面测试，不冒充重新在线跑完 58 篇。

## 2026-10-10：默认普通启动并复用窗口

## 尚待独立验证

### 跨机构、跨设备的实施方案

1. 每个机构/账户使用独立的本地 profile。认证仍由用户所在设备的浏览器完成；迁移设备时迁移 DOI 队列、检查点和经过哈希核验的正文，不复制 cookie、SSO ticket 或验证码令牌。本补丁复用现有 profile 配置，未实现新的机构目录。
2. 出版社适配器只描述官方入口、可见机构选择和交付行为；机构名称来自当前页面，不写死“科院”。多个可见机构或没有已记住选择时交给用户确认，不自动猜订阅。实际无权限保留独立终态，不无限要求重新登录。
3. 每篇按入口解析、访问检查、交互、正文交付、身份/角色验证、独立审计恢复。当前补丁保留同一进程中的挑战页面，检查点保存访问检查阶段和状态历史；进程退出后的长期恢复、明确的交互完成事件与全流程总预算是后续扩展，不把已有单操作超时说成已完成全流程预算。
4. 报告按 DOI 保存全部尝试，并分别展示最新状态和最佳已验证正文；设备/机构切换不能把另一环境的历史成功当成本次下载成功。获取失败、权限受限、验证码、运行器超时及审计警告分别呈现。
5. 后续资格验收固定至少两个真实机构、两台设备及 Windows 与另一操作系统，选定各机构确认有权限的阳性对照和无权限阴性对照；逐场景检查首次登录后续传、第二篇复用、会话过期、进程重启与设备迁移。成功必须有目标 DOI/正文角色/文件哈希证据，不能用受控 HTML 的机构标签替代真实机构测试。

本次回归不能保证出版社永不要求验证码，也不能证明不同真实机构、macOS/Linux、新设备的完整体验。
历史 Science 挂起具体调用位置未复现；新增超时和完成事件处理覆盖了已发现的阻塞风险，现场结果仍须如实记录。
