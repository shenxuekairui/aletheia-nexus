## 持续工作规则

- 分析已有结果 → 找主要瓶颈 → 提出有实质差异的候选 → 并行离线筛选 → 小型开发对照 → 新论文验证 → 集成有效机制 → 下一轮。
- 每轮考虑 2–4 条候选路线，但不为凑数量重复已无效的实验。优先复用原始响应、材料和评分；代码分析、材料准备、源审并行。
- 统一报告严格字段查准/查全、必需信息覆盖、完整记录、对象/阶段/条件关联错误、新增错误、退化、成本、耗时和失败。科学错误、遗漏、结构损失、评分口径分开。
- 不把具体论文答案、条件、材料名或评测参考写进产品逻辑。开发样本只用于诊断，通用收益需未参与调参的新论文支持。
- 运行中不修改冻结输入、参考和评分；失败保留在分母。实验性路线不自动成为产品默认，不以更多输出或工程测试替代科学收益。
- 只做与修改相关的必要工程验证；已有通过检查不因上传而重复。连续无明显收益时改变信息处理顺序或材料路径，不无限叠加提示/复核轮次。
- 保护原文、规范解析工件、历史与本地模式；遵守现有预算，不合并主分支或正式发布。持续执行受实际工具能力与授权边界约束。

## 工程与科学瓶颈

既有标准流程已交付结果的原响应→结构化记录回放未发现科学内容静默丢失；本轮私有摘录适配器则因非逐字匹配丢掉部分正确片段，不能混为一谈。当前主要瓶颈是复合字段漏限定、事实跨字段缺少明确关联、图中数字/单位误读、对象与阶段混淆，以及额外断言引入错误。引用能定位不等于充分支持整个长字段。

独立工程修复：已隔离限定字段输出的提取指令，避免进入复核/定向修订阶段；缓存纳入实际请求及 Schema。只改变比较请求时复用文献结果；提取重算但结果相同时仍可复用比较。相关 13 项 Mock 检查通过（分次执行），保留原始记录；没有重复全量套件，不能先算作科研准确率提高。

本轮修复已知来源、页码未知的补充材料请求：保留有效提取及请求，状态为PARTIAL/needs_input，
相同输入恢复不再收费；若复核新增尚未读取的具体页面，则不误缓存。真实B响应零API重放

导出另经定向验证；Ruff与差异检查通过，未重复全量套件。原始失败和当时源码分别保留。
