## 持续工作规则

- 分析已有结果 → 找主要瓶颈 → 提出有实质差异的候选 → 并行离线筛选 → 小型开发对照 → 新论文验证 → 集成有效机制 → 下一轮。
- 每轮考虑 2–4 条候选路线，但不为凑数量重复已无效的实验。优先复用原始响应、材料和评分；代码分析、材料准备、源审并行。
- 统一报告严格字段查准/查全、必需信息覆盖、完整记录、对象/阶段/条件关联错误、新增错误、退化、成本、耗时和失败。科学错误、遗漏、结构损失、评分口径分开。
- 不把具体论文答案、条件、材料名或评测参考写进产品逻辑。开发样本只用于诊断，通用收益需未参与调参的新论文支持。
- 运行中不修改冻结科学输入、参考和评分。按用户追加规则，执行/交付失败与科学错误分开：技术失败最多一次同条件恢复，每任务只评分一个有效答案；失败尝试不进入科学分母，但保留计划任务交付率、排除数量及所有尝试的费用和耗时。有效答案中的遗漏、关联错和未确认扩写不能按技术失败排除；两模型另报共同有效任务。历史单次交付口径保留，不用新视图静默覆盖。实验性路线不自动成为产品默认，不以更多输出或工程测试替代科学收益。
- 只做与修改相关的必要工程验证；已有通过检查不因上传而重复。连续无明显收益时改变信息处理顺序或材料路径，不无限叠加提示/复核轮次。
- 保护原文、规范解析工件、历史与本地模式；遵守现有预算，不合并主分支或正式发布。持续执行受实际工具能力与授权边界约束。

## 工程与科学瓶颈
