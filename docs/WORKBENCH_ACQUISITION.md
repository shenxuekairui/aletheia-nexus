# 本地工作台：论文获取与 SI 支持边界

更新：2026-10-29。本文件说明新增应用适配层；已有 CLI、MCP 和主文身份核验策略保持各自入口。

## 复用与新增

| 能力 | 实现及边界 |
| --- | --- |
| DOI、中文书目身份、机构浏览器、CNKI、已授权官方 API | 复用 `acquire.access` 引擎与 `PaperRequest`；不模拟 CLI，不受 MCP 公共 DOI 子集限制 |
| 已取得的书目元数据 | 仅从本次引擎真实返回且 DOI 一致的 metadata 补齐缺失作者/年份/期刊等可变字段，逐字段记录来源 DOI 与 sidecar 哈希；不覆盖已有人工编辑，不新增隐式网络请求，不改原题或来源 sidecar |
| 输入预览 | TXT、CSV、JSON 和粘贴列表；保留合法书目字段与逐行错误；按身份去重，不把分类或标签当科学身份 |
| 英文标题找 DOI | 使用既有 Crossref 传输和解析器。只有标题规范化后精确、唯一、且作者/年份/期刊约束均一致才自动解析；相似候选、多 DOI 同题或冲突交给人工选择 |
| 中文无 DOI | 保留原 CNKI 标题/书目核验路线。需要明确启用机构浏览器策略；不会捏造 DOI，也不会自动拿英文 Crossref 的第一条结果顶替 |
| SI | 官方文章页须具有唯一目标 DOI 及明确附件链接；受支持官方仓储另严格核对同版本元数据、清单与校验值。只跟随明确关联，不扫描全站或猜测下载地址 |
| 主文/SI 状态 | 主文 `VERIFIED` 仍由原核验引擎判定。SI 失败不修改成功主文。PDF SI 复用 `REGISTERED/DECLARED` 父文关联契约，外加独立官方来源 receipt；不会冒充主文身份验证 |
| 布局 | 正文位于所选分类根部；全部关联附件共用该分类唯一 `SI/`。文件名基于主文实际基础名称加 `__SI-01` 等后缀及真实扩展名；不创建每篇专属目录 |
| 安全改名后的恢复 | UI 获取检查点可按唯一 PDF 哈希、来源 sidecar 哈希和 DOI 重新定位；旧检查点不改，另存新版本及重定位记录；原引擎仍复核缓存文件 |

标题检索只解决书目身份，不代表 PDF 已获得或已验证；Crossref 召回也不是全部相关论文。没有可靠候选时请补充 DOI/作者/年份，或使用明确支持的 CNKI 场景。

## 官方附件覆盖

通用适配器只读取明确的补充信息、补充材料、源数据、同行评议文件、Reporting Summary 链接；这些角色分开登记。正文下载按钮不算 SI。

已识别的官方主站/配套 CDN 家族包括 Nature/Springer、ACS、RSC、Wiley、Elsevier、Science、PLOS、MDPI、PNAS、Frontiers。已有获取证据将来源标为 publisher 时，也可使用其同主机的明确附件链接。这是保守的来源主机与链接策略，**不表示已逐一实测这些出版社的全部页面结构**。部分 ACS、Wiley、Elsevier 附件接口已有明确格式适配；未覆盖的脚本目录、无法确认 DOI 的页面、接口或外部附件主机仍会返回未找到/未覆盖诊断。

调用者允许机构浏览器时，先观察已有的 DOI 匹配官方文章页；缺少可用文章页时，可在同一允许会话创建自己的临时页打开明确官方地址或 DOI。
既有用户标签页不导航、不刷新；自有可用文章页保持到本篇附件处理结束后关闭。若文章页或附件另需人工验证，保留对应页面并报告需要人工，
本批结束后从“选择失败论文重试 / 仅补 SI”选择待补论文和同一会话。SI 暂无实时等待人工后自动续取；不能把正文已打开、HTTP 200 或 PDF 查看器页面当作附件已保存。

PDF 校验真实 PDF 结构与页数；Office Open XML 检查 ZIP 格式和对应主文档成员；传统 XLS 检查容器签名；文本拒绝明显 HTML 登录页和二进制内容；图片做适用的签名检查。ZIP 仅保存登记，不解压。其他获准类型安全保存登记，**不保证能解析科学内容或排除文件内恶意宏/脚本**。软件不自动打开附件或执行文件。

只有角色为 SUPPLEMENT 的 PDF 进入既有 PDF SI 解析与检索。其他 PDF 角色和非 PDF 文件仍作为附件展示。失败、发现数量、截断、主文状态是否保持均有独立结果字段。最大附件数与单文件字节上限实际生效。URL 先通过现有安全传输，每次重定向继续复核，不复制浏览器 Cookie 给附件 HTTP 请求；受机构会话保护的 SI 可能明确失败。

已选择获取 SI 时，只要任一成功正文的附件失败、部分成功、达到数量上限而截断、未找到或尚不支持，整体任务会标为“部分完成”，附逐篇状态和覆盖提示；正文仍保留原来的 `VERIFIED`，成功篇数仍按正文计数。未找到不代表论文没有 SI，不支持也不等于已获取齐全。

父文 article ID、PDF/来源哈希和附件哈希是归属依据；文件名只用于阅读。重命名后保留原始官方 receipt 字节，通过文库登记的 source locator 继续定位旧来源记录并复用同一附件。没有静默重写历史来源证据。

## 配置与任务控制

底层 `get_acquisition_defaults()` 初值仍为仅公开获取、无机构浏览器；**新 UI 工作区**补入公开先行、机构浏览器回退、可见会话、SI 开启、原生文本优先自动解析与 1 秒普通间隔。
已有显式偏好和预设不静默覆盖，CLI/MCP 默认不因此改变；OCR 和付费标题翻译仍关闭。关闭 `public_only` 必须启用 `browser_enabled`。
出版社官方 API 使用原引擎的环境认证，与设置顶部的 DeepSeek 模型配置分开；二者都不把密钥放进任务或预设，也不因检测到密钥就自动开启收费或材料外发。
公共策略会关闭官方认证 API 和浏览器路线，矛盾配置在联网前拒绝。

`get_acquisition_defaults()` 从真实引擎参数提供超时、路线/候选/尝试预算、元数据、重试、代理、浏览器配置、CNKI 专用参数等。人工等待使用顶层 `interaction_policy`、`interaction_timeout` 和 `auto_resume_interaction`，不再暴露被覆盖的内部回调。
常用区默认开启“人工验证完成后自动检测并继续”，仅在正文等待模式生效；关闭后需手动要求重新检查。等待 0 表示不限时，正数由该次等待期限约束；显式暂停仍须恢复，检测到页面放行也不会越过暂停或取消。

- 普通 `bulk_interval`：完成一篇后、开始下一篇前的调度间隔。
- `browser.cnki_paper_interval`：同一浏览器会话中 CNKI 获取路线的最小静默间隔；复用原引擎时钟。
- `retry_backoff`：单篇失败重试的指数退避，区别于论文间隔。
- 网络 `timeout`、浏览器 `request_timeout`、`navigation_timeout`：原引擎各相应阶段超时，不伪装成总任务时限。

三种人工策略分别是等待、跳过继续、暂停批次等待决定。任务中心通过合作式边界控制：正在传输或验证的文件不会被强杀，普通暂停/取消/跳过在论文边界生效；浏览器发出人工验证通知时可继续/跳过/取消。跳过动作保留实际引擎状态及原因。没有验证码破解、MFA/订阅绕过，也不盲重试限流/权限拒绝。

任务页面关闭不会取消后台线程；进程终止后的状态由统一任务中心诚实标为中断。开始工作前即把检查点指针持久登记到任务中心，取消或中断后也可恢复；按原生检查点恢复会复核文件和来源。UI 检查点重定位只适用于已登记适配目录；任意旧 CLI 检查点/科研契约若显式绑定旧路径，仍由文库风险预检拒绝不安全改名。未知目录外的引用无法自动审计，不能据此宣称所有外部引用都已迁移。

任务结束后可只勾一篇或几篇未成功论文重试，或选择“仅补 SI”。确认窗口复核真实来源、检查点、实际目录与标签，已验证正文经门禁后复用；补 SI 保留当前正文名，不默认重做付费标题翻译。
每篇正文和 SI 尝试结束后，按所选设置依次翻译、同步命名、解析，再调度下一篇。标题翻译共享整批原生调用账本及费用上限，缓存/人工译名优先；未知费用保留预留并阻止新 HTTP，不静默补预算。
正文成功数按论文请求计，解析数按 PDF 文件计（含 SI），正文全部验证后仍可能处于后处理。科学排版清理仅作用于新名称呈现，不修改原题、人工译名、缓存或原始证据，也不自动改名历史文件。
