# v0.4.1 Discovery Reliability Hardening

> Full-text Discovery（全文发现）可靠性强化开发说明。

Aletheia Nexus v0.4.1 不扩展新的 Provider（数据源适配器），而是优先把已经建立的 OpenAlex + Unpaywall Discovery（发现）能力变成更可靠、可批量、可追踪的基础能力。

## Scope

本阶段完成：

- Retry（重试）与 Exponential Backoff（指数退避）
- Provider（数据源）独立失败隔离
- Provider 级稳定失败状态
- attempts（尝试次数）记录
- Batch Discovery（批量发现）
- 标准化 DOI 后稳定去重
- `PARTIAL_SUCCESS`（部分成功）语义
- 配置与输入边界验证
- 自动测试
- 真实网络人工验收脚本

本阶段刻意不做：

- 新增 Crossref / DataCite / Europe PMC / arXiv / CORE 等 Provider
- 并发、异步、缓存、复杂限流调度
- PDF 下载
- CARSI / SSO / 浏览器登录
- PDF 文件与论文身份验证

这些边界用于避免在真实需求和瓶颈尚未出现前提前增加系统复杂度。

## Retry semantics

仅以下暂时性错误自动重试：

```text
NETWORK_ERROR
RATE_LIMITED
SERVICE_ERROR
```

以下错误不会因为重复请求而自动恢复，因此不重试：

```text
NOT_FOUND
REQUEST_ERROR
PARSE_ERROR
CONFIGURATION_ERROR
```

每个 Provider 独立重试。一个 Provider 失败不会阻断另一个 Provider。

## Provider status

当前 Provider 级状态包括：

```text
SUCCESS
NO_CANDIDATES
NOT_FOUND
SKIPPED
CONFIGURATION_ERROR
REQUEST_ERROR
NETWORK_ERROR
RATE_LIMITED
SERVICE_ERROR
PARSE_ERROR
ERROR
```

`ProviderDiscoveryResult` 同时记录 `attempts`，保留实际执行过程。

## Batch Discovery

公开入口：

```python
from aletheia_nexus.acquire.discovery import discover_full_text_batch
```

批量层执行：

```text
原始 DOI 输入
↓
逐条 DOI 标准化
↓
按标准化 DOI 稳定去重
↓
逐篇 Discovery
↓
Provider 独立 Retry / Failure Isolation
↓
候选去重与排序
↓
稳定 Batch Status
```

当前批量状态：

```text
SUCCESS
PARTIAL_SUCCESS
NO_CANDIDATES
NOT_FOUND
INVALID_DOI
ERROR
```

`PARTIAL_SUCCESS` 表示至少已经获得有效全文候选，但同时有一个或多个 Provider 发生真实失败。正常的 `NO_CANDIDATES` 或未配置 Provider 导致的 `SKIPPED` 不会被误判为部分失败。

Batch 当前刻意采用顺序执行。只有真实数据证明性能成为瓶颈之后，才考虑并发或异步实现。

## Real-network acceptance

真实 Provider API 使用独立人工验收脚本：

```powershell
python scripts/manual_discovery_acceptance.py --unpaywall-email "person@example.org" 10.1038/nphys1170
```

脚本输出：

- Batch Status（批量状态）
- Provider Status（数据源状态）
- Provider Attempts（尝试次数）
- Candidate URL（候选链接）
- URL Type（链接类型）
- Access Type（访问类型）
- Version（论文版本）
- Host Type（托管来源类型）
- Provenance（来源追踪）

真实网络验收不放入 CI（持续集成），避免外部服务短暂异常造成随机失败。

## Next decision

v0.4.1 完成后不默认继续堆叠 API。

下一阶段首先应建立真实文献集并测量：

- OpenAlex + Unpaywall 的实际覆盖率
- 直接 PDF、Landing Page（落地页）、Repository（仓储）候选比例
- Provider 重叠与互补程度
- 主要缺失类型
- 不同出版社、年代、学科和 OA 状态下的失败模式

只有确认稳定、重复的真实缺口后，再决定增加哪一个 Provider。
