[English](WORKBENCH_TROUBLESHOOTING_20261103.en.md)

日期：2026-11-03。复现基线：v0.8.1，Windows x64，Python 3.12.15，安装 UI 与 MCP 可选依赖。本报告记录一次本地导入、解析、AI 总结、查看和导出的完整排查过程。输入材料以 PDF-A、PDF-B 匿名表示，不随修复提交原论文、模型响应、用户文库、密钥或本地任务记录。

“补丁修复”表示本次代码包含相应改动，不表示上游已合并或发布。发布状态以对应 PR 和发行记录为准。

## 2. Windows 路径问题

### 现象与定位

导入任务已完成，原 PDF 和入库来源记录均存在。失败发生在 `WorkbenchResearch._snapshot()` 复制研究材料时，目标形如：

```text
<workspace>/research-workspace/materials/<64位PDF指纹>/json/<64位来源指纹>.acquisition.json
```

该次目标路径长 261 个字符。系统抛出的 `FileNotFoundError` 被通用提示解释成了原 PDF 不存在，导致反复导入和解析仍失败。

### 修复与兼容

- 立即处理：启动时通过 `--workspace` 指定更短目录。迁移前停止运行中的任务、备份设置和任务数据；历史工件含绝对定位，不能对已有成功结果做盲目字符串替换。此次旧工作区保留为备份。
- 通用补丁：工作台与 CLI/MCP 共用的研究服务使用同一个路径选择机制。Windows 上，预计来源快照路径达到 240 字符时，改用工作区内的 `m/<PDF指纹前24位>/...` 存储定位。完整 PDF SHA-256、完整来源记录指纹以及来源核验不变。
- 短目录只是定位方式，不是缩短论文身份。既有不可变复制逻辑仍检查目标文件内容；发生短目录碰撞时拒绝覆盖，而不是接受错误材料。
- 历史记录不迁移、不重写。短目录之后仍超过 259 字符时，在复制前返回 `workspace_path_too_long`，提示缩短工作区，不再将其解释为用户文件丢失。
- 原子导出、规范解析工件和本地 PDF 登记原先把目标/源文件名再次拼入临时文件名；即使最终路径合法，临时路径也可能超长。补丁将临时名称改为同目录的 UUID，保留独占创建、原子替换和来源文件覆盖保护。补充测试复现这一问题。

涉及：`src/aletheia_nexus/research_app.py`、`workbench/research.py`、`workbench/messages.py`、`content/export.py`、`content/schema.py`、`content/local.py`。

## 3. PDF 页面几何异常

PDF-A 的一个示例：MediaBox 为 `[0, 0, 549.9213, 802.2047]`，CropBox 为 `[0, 802.2048, 549.9213, 0]`，导致高度为负。原生解析器报 `CropBox must have positive dimensions`，119 页未提取到正文。

这是输入格式问题，与路径修复相互独立。浏览器能够打开 PDF，不等于解析器可以安全解释其页面坐标。

处理方法：优先取得有效原版；确需修复时另存派生 PDF，记录与原文的关系，逐页核对渲染与文字位置，再作为新版本登记。此次没有修改原文、放宽几何校验或声称已经修复该 PDF。

## 4. 字符上限、执行模式与密钥

### 先检查实际执行计划

`max_input_characters` 限制的是实际结构化材料或请求的序列化字符数，不仅是正文长度。来源信息、块结构、引用和跨篇比较均会增加体积。

本次本地测量：

| PDF-B 取材范围 | 模型材料 JSON 字符数 |
| --- | ---: |
| 全部 14 页 | 163121 |
| 第 1 页 | 6998 |
| 第 1—3 页 | 15155 |
| 第 1—5 页 | 46780 |

这些数字只适用于本次解析版本，不是通用换算比例。200000 足以容纳该次材料，不保证任意论文或后续补充请求都能容纳。

处理步骤：

1. 确认选定论文、页码和解析版本；优先缩小不必要的范围。
2. 在核对模型单价、调用次数和费用后调整字符上限。不要关闭校验或静默提高费用额度。
3. 已载入历史计划、已提交任务与新默认值相互独立。点击“验证并预览实际计划”，核对 `budget.max_input_characters`；使用专家契约时核对契约中的值。
4. 修改默认值后重新打开 AI 研究页，新建计划。历史失败记录保留，不作为新设置已经生效的证明。

### 本地准备不等于模型执行

`local` 模式不会生成模型总结。需要模型分析时选择 `parsed` 等适当模式，检查当前进程已配置 DeepSeek API 密钥，再核对并执行计划。仅生成本地计划不会扣模型调用次数。

本次通过工作台界面执行的后续任务使用 200000 字符上限、最多 10 次调用、2 CNY 费用上限，实际调用 2 次，按所填单价估算约 0.702408 CNY。该数值是软件估算，不是服务商账单。

返回状态为 PARTIAL：已经有总结，但模型明确要求补查部分图表。执行结束、引用能定位、科学支持已核实是不同状态，不应合并成“全部完成”。

### 密钥生命周期

工作台默认会话密钥在进程重启后失效。用户可明确选择使用已有的 Windows 用户凭据保存功能；修复和部署不能擅自替用户开启持久保存。不要把密钥放入聊天、配置示例、任务 JSON、PR 或日志。

## 5. 导出下载修复

### 复现

在“研究成果”点击“导出此版本”，再点击 `report.md`。原行为产生新标签页，响应头为 `inline; filename="report.md"`；浏览器没有触发下载事件。原生 ZIP 已生成，因此不是导出引擎没有工作。

### 补丁

- 导出链接显示“下载 文件名”，使用同页下载属性和 `?download=true`。
- `/an-file/{token}` 增加可选布尔查询参数 `download`：下载请求返回 `attachment`，默认仍是 `inline`，保留 PDF 和报告预览。
- 原有文件令牌、目录边界、哈希复核和同源限制不变，不将整个目录挂载为公共文件服务。
- 用户操作为“导出此版本 → 下载 report.md / native-results.zip”，不是点击导出后自动保存到任意本地目录。

涉及：`src/aletheia_nexus/workbench/ui.py`。

## 6. 完整可视报告

新增 `visual_report.py`，由工作台原生导出流程调用。导出格式包含 HTML，并在结果页给出“打开完整可视报告”与“下载 report.html”入口。

报告包括：主要主张卡片、完整字段内容及上下文、步骤记录、逐项引用、材料缺口和补充请求、来源与任务参数，以及用于本地核对的内嵌原页。优先展示模型明确请求的图表页，每份来源最多嵌入 6 页，1600 像素上限；这不代表已展示整本 PDF 的所有图片。

边界：

- 复用已保存结果，不新增模型调用，也不把界面排版视为新科学结论。
- 仅在明确选择 HTML 格式时读取和嵌入原页；既有调用未指定格式时保持原有文字导出行为。
- 原页渲染前后核对来源指纹；核对失败时不采用此次图像。原文不在本地或渲染器不可用时，保留可读文字并提示缺少原页。
- 引用、标题、模型文字和来源信息均经过 HTML 转义，不作为脚本执行。图片内嵌，无需远程图片、字体或 CDN。
- 多份结果使用结果身份和文献 ID 共同区分来源，避免不同历史版本复用同一个 ID 时混淆引用和图片。
- 打印按钮展开图片和引文，等待图片解码后调用浏览器打印，可由用户另存为 PDF。补丁不自动调用远程模型补图，也不宣称生成了已经核实的完整论文解读。
- 原生结果、历史、来源定位和待核对信息保留。HTML 是可视化派生文件；原生 ZIP 用于保存原始结构与复核数据。

涉及：`workbench/visual_report.py`、`research.py`、`ui_research.py`。此功能目前接入工作台导出，未修改 CLI/MCP 的格式契约。

## 7. MCP 的实际能力

MCP 实现位于 `src/aletheia_nexus/mcp_server.py`，入口是 `aletheia-nexus mcp serve`。它提供列举、准备、解析、检索、读取原页和研究结果等工具，供外部 AI 客户端调用；不能把安装 MCP 依赖等同于已经在某个聊天客户端建立连接。

本次没有新增连续聊天 UI，也没有声称完成 MCP 客户端接入。用法和边界见 [V08_ENTRYPOINTS.md](V08_ENTRYPOINTS.md)。

## 9. 提交范围与数据保护

补丁只应包含通用代码、合成测试和本文档及英文对照。不要包含本地文库、论文 PDF、带原页图片的用户报告、原始模型结果、授权令牌、凭据、绝对用户目录或本地安装环境。
