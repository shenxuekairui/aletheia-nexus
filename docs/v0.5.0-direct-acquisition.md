# v0.5.0 Direct PDF Acquisition

> Aletheia Nexus stable primitive for trustworthy direct-file retrieval.

**Version:** 0.5.0

**Layer:** Direct PDF Acquisition + Validation（直接 PDF 获取与验证）

**Status:** RELEASED / STABLE BASELINE
**Main merge:** `6c8091b35c040817d347a8ced6d71c50956c5e83`

## 1. Goal

v0.5.0 takes exactly one provider-reported PDF candidate and answers:

> Can this route be retrieved safely, and do the resulting bytes support treating the
> file as the requested main article?

```text
FullTextCandidate(url_type=PDF)
↓
safe retrieval
↓
PDF structure validation
↓
paper identity validation
↓
document-role validation
↓
VERIFIED local PDF + acquisition sidecar
```

Core invariant:

```text
Candidate ≠ downloaded file
Downloaded file ≠ valid PDF
Valid PDF ≠ target paper
Target paper ≠ main article
```

Only a valid PDF with identity `MATCH` and document role `ARTICLE` can become
`VERIFIED`.

## 2. Stable scope

v0.5.0 owns:

- one direct PDF candidate at a time;
- HTTP(S) URL safety checks;
- best-effort DNS preflight checks;
- manual redirect validation;
- streaming download;
- default 100 MiB file limit;
- SHA-256 calculation while streaming;
- bounded retry for transient failures;
- PDF header/parser validation with `pypdf`;
- encrypted-PDF handling through `pypdf[crypto]`;
- CFF / Type1 extraction support through `fontTools`;
- page-count/encryption reporting;
- limited first-pages text extraction;
- DOI-first identity evidence;
- conservative title fallback;
- conservative Supporting Information detection;
- atomic file promotion;
- `.acquisition.json` provenance sidecar;
- optional `_unverified/` retention for Human-in-the-loop（人在回路中） review.

It does **not** own:

- Landing Page → PDF resolution;
- automatic multi-route fallback;
- CARSI / SSO / browser automation;
- CAPTCHA or anti-bot circumvention;
- paywall bypass;
- scientific-content parsing;
- batch acquisition orchestration.

Those boundaries remain intentional after v0.5.1.

## 3. Public API

```python
from aletheia_nexus.acquire.fulltext import acquire_direct_pdf

result = acquire_direct_pdf(
    candidate,
    output_dir="downloads",
    expected_title="Optional known title",
)
```

The input must be a `FullTextCandidate` whose `url_type` is `PDF`.

## 4. Stable result statuses

```text
VERIFIED
RETRIEVED_UNVERIFIED
SUPPLEMENT
MISMATCH
INVALID_PDF
AUTH_REQUIRED
ACCESS_BLOCKED
NOT_FOUND
TOO_LARGE
UNSAFE_URL
REDIRECT_ERROR
REQUEST_ERROR
NETWORK_ERROR
RATE_LIMITED
SERVICE_ERROR
ERROR
```

Access semantics are deliberately conservative:

```text
401 → AUTH_REQUIRED
403 → ACCESS_BLOCKED
```

HTTP 403 alone does not prove that user login or institutional entitlement is the
cause. It can also represent WAF（Web 应用防火墙）, anti-bot, IP policy or another
server-side restriction.

This distinction was added after the fixed CDI corpus showed an Open Access RSC route
returning HTTP 403 to an automated client.

## 5. Retrieval and retry contract

Defaults:

```text
max_bytes       100 MiB
max_redirects   8
timeout          30 s
max_attempts     3
backoff_base      1 s
```

Only these expected transient failures are retried:

```text
NETWORK_ERROR
RATE_LIMITED
SERVICE_ERROR
```

These are not retried automatically:

```text
AUTH_REQUIRED
ACCESS_BLOCKED
NOT_FOUND
TOO_LARGE
UNSAFE_URL
REDIRECT_ERROR
REQUEST_ERROR
```

Programming errors and local filesystem failures propagate instead of being disguised
as remote acquisition failures.

## 6. PDF validation

Transport success is never enough.

A retrieved resource is inspected for:

- `%PDF` file marker;
- parser usability;
- page count when available;
- encryption state;
- extraction viability.

`Content-Type: application/pdf`, a `.pdf` suffix or HTTP 200 never independently implies
success.

Permission-encrypted PDFs that can be opened with an empty user password are inspected.
A locked encrypted PDF remains unverified; metadata title alone cannot promote an
unreadable file.

## 7. Paper identity policy

Identity states:

```text
MATCH
MISMATCH
UNKNOWN
```

Primary evidence is exact target DOI evidence in inspected PDF text.

When a known title is supplied, conservative fallback evidence may use:

- exact normalized title occurrence in inspected text; or
- very strong similarity to the dedicated PDF metadata title.

Loose whole-page vocabulary overlap is deliberately excluded because scientific terms
are too repetitive to serve as reliable identity evidence.

Missing DOI evidence alone yields `UNKNOWN`, not `MISMATCH`.

## 8. Main article versus supplementary material

A valid PDF can still be Supporting Information（补充材料）.

Strong supplement evidence can come from:

- source filename;
- PDF metadata title;
- text near the beginning of the document.

The text check is intentionally limited to the document lead so an article that merely
mentions “Supporting Information” later is not rejected.

A detected supplement returns `SUPPLEMENT` and cannot become the verified main article.

## 9. Storage and provenance

Verified files use deterministic names derived from DOI and content hash:

```text
<safe-doi>-<sha256-prefix>.pdf
<safe-doi>-<sha256-prefix>.acquisition.json
```

The sidecar records:

- target DOI and optional expected title;
- input candidate semantics and provider provenance;
- requested/final URL;
- redirect chain;
- HTTP status and Content-Type;
- byte count and SHA-256;
- PDF validation report;
- identity/document-role evidence;
- retry attempts and elapsed time;
- acquisition timestamp.

Temporary `.part` files are removed on failure. Newly promoted PDFs are rolled back if
sidecar creation fails, while already-existing correct PDFs are protected from deletion
if a later sidecar refresh fails.

## 10. Security boundary

Each request and redirect target must pass Acquisition URL safety checks. Obvious local,
private, link-local, reserved and otherwise non-global addresses are rejected where the
system can establish that fact.

DNS checking is a **preflight defense**, not adversarial DNS-rebinding-proof connection
pinning. Stronger network isolation would require a different transport architecture or
restricted execution environment.

## 11. Release acceptance

Before release, deterministic CI passed on Python 3.11 and 3.14 with:

```text
editable install  ✅
pip check         ✅
Ruff format       ✅
Ruff static       ✅
compileall        ✅
pytest            ✅
```

Representative real-network acceptance covered:

- genuine article PDF → `VERIFIED`;
- CaltechAUTHORS Supporting Information → `SUPPLEMENT`;
- HTML passed as a PDF route → `INVALID_PDF`;
- publisher routes returning non-PDF interstitial content → conservative rejection;
- authorization/access boundaries;
- redirects and repository-hosted files.

The fixed CDI corpus then exposed the final 403 semantic correction before merge.

## 12. Relationship to v0.5.1

v0.5.1 does not replace this layer. It produces more concrete file candidates and then
hands them back to this stable primitive:

```text
Landing / Repository / Resolver route
↓
v0.5.1 Route Resolution
↓
Derived PDF Candidate
↓
v0.5.0 Direct PDF Acquisition + Validation
↓
VERIFIED / explicit non-success
```

This separation is the core reason v0.5.1 can maximize path-finding capability without
weakening file correctness.
