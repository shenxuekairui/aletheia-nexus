## 最小架构

新增 `processing` 包，与获取、解析并列：

`JSON Task → 验证来源 → Task Package → Provider → 结构与引用校验 → 派生结果 → 导出`

职责拆分：`contracts`（版本化任务和响应约束）、`materials`（复用证据包、
任务级选页/补充/修订）、`provider`（一个真实 HTTP 适配器及可替换协议）、
`engine`（批量、有限补充、恢复和成本台账）、`results`（引用检查、导出、人工修订）、
`processing_cli`（用户入口）。没有数据库、向量库或 Agent 框架。

选择 JSON，沿用仓库惯例并避免 YAML 依赖。按用户指定选择 DeepSeek Flash 的 Responses API，复用
已有 httpx；一个接口支持文本、图像和 JSON Schema 请求。实测服务仍可能返回坏 JSON
或额外字段，因此本地验证不可省略。模型由用户明确指定，
不自动路由。官方依据：[Responses API](https://api-docs.deepseek.com/api/create-response/)、
[图像输入](https://api-docs.deepseek.com/guides/vision/)。先前考察的 OpenAI 方案由此替换，
不同时维护两个提供商。Schema 只约束
结构；可定位引用也不代表科学支持。DeepSeek 的 Responses API 为无状态接口，不宣称平台所有日志零保留。
模型名为 `deepseek-flash`；用户授权本轮累计测试最高 100 元人民币。

所有场景共用用户字段、对象、阶段、字段与步骤关联、主张性质和引用。合成案例仅在
示例和测试中出现。原值与单位保留，不做自动单位换算。AI 不能生成“人工确认”。

任务材料包保留规范读法、补充页、SI、用户备注和带作者/理由的修订覆盖层；
不修改规范工件。文本路径复用 v0.7；直读路径只依赖原 PDF 身份校验和指定页图像。
页面渲染复用既有 Poppler 外部依赖，增加有界独立入口，不启动 OCR。

## 真实执行驱动的调整

- 默认关闭 reasoning（`none`），非思考模式 temperature=0。实测 `low` 的 9000
  输出 Token 上限被耗尽而没有完整结果；用户仍可显式选择 reasoning 并增加预算。
  不能由这次样本推断思考模式普遍无用。
- 阅读摘要允许 `raw_value=null`，其原读法保存在引用中；数值、布尔值和规范化
  结果仍须保留原值。用数值提取的约束强制摘要，会制造虚假的“原始值”。
- 引用仅对空白和拉丁排印连字（如 ﬁ）作等价匹配，不用 NFKC，避免改写上下标、
  负号、单位和化学符号。不自动拼接跨块引文。
- 格式/引用失败允许一次有明确诊断的模型修正，和补充材料分开计数；两者共享
  HTTP 次数与费用预算。无效候选保留；不能因为第二次调用耗尽就接受错误结果。
- 材料包 v1 的 builder=2 保存本地定位路径，发送模型前剔除。重新导出前检查 PDF
  哈希，文件已改变时不提供可能误导的原文链接。
- 费用预留在 HTTP 前落盘；评测脚本用进程锁保护累计台账。崩溃后未获得用量的
  调用仍按保守预留计费。没有新增数据库。
- 实测条件数值可以全对、步骤关联却错误；提示词 v5 明确限制 step_ids 的含义。
  这不是可由 Schema 自动验证的科学规则，仍需原页复核和独立评测。
- 导出格式为任务可选项，默认保留三种；离线 export 可覆盖格式选择，避免为展示变化
  再次调用模型。独立主张导出到 claims.jsonl，保持 records.jsonl 的逐记录契约。
- 人工修订复用一个入口，支持字段记录和按索引定位的主张；确认来自显式修订历史。
  不把 AI 生成的主张自动标为人工确认；改写并取消确认只影响被修改的对象。
- paper15 持续出现数组未闭合及主张层级错误，v6明确对象层级并省略未请求的步骤；
  有限实测仍失败。保留明确失败，不引入猜测括号或重排模型结果的自动修复器。
- 新论文暴露两类资源问题，采用局部修复：获取阶段把 pypdf 的解压上限异常记为
  文本检查受限，身份验证规则不变；原生布局在交给 pdfminer 前执行同一内容流检查，
  超限页记为 PAGE_EXTRACTION_FAILED，继续保留其他页。未提高或关闭依赖的资源上限。
- 稠密图形的矢量文字候选匹配可能形成平方级开销。限制候选数为5000、成对比较为
  250000；达到上限时保留候选区域、原生正文及 VECTOR_TEXT_SCAN_LIMIT 警告，交给
  视觉核对或显式启用的 OCR。不猜测图中文字。相比全面重写布局/空间索引，这一
  有界处理更小，代价是复杂图区域的自动检测更保守。后端版本1.19.7，规范仍为v3。

当前工程能力覆盖阶段2–5；阶段6已完成开发集执行和独立10篇、三任务×三路径
的冻结评阅。科学目标未达，详见V08_ACCEPTANCE.md；仍为未发布开发版。

冻结评测后采用v7提示词明确补页后重新判断、实验体系隔离和定性条件保留；不引入
学科专用规则。缺失值校验增加记录/字段诊断，Provider只增加HTTP状态码，便于区分
请求拒绝和传输失败。没有降低引用校验标准或自动猜测修复科学内容。

完整v7回归又发现：补页实际成功，模型仍复述旧候选中的缺页判断。三个开发案例的
配对重放支持一个局部调整：补充请求传待查问题及当前/新增页面覆盖，独立重新提取，
不再携带整份旧答案。与继续增加“请重新检查”提示相比，这直接去掉错误答案的输入
影响；代价是新答案可能丢失旧答案中的正确内容或引入新错。旧候选与原包仍落盘，
补充失败回退不变，不自动合并两份答案。覆盖元数据只表示实际文本/图像已提供，
不证明支持任何主张。提示词升至v8以隔离缓存，不改任务、结果或解析工件版本。

用户在 2026-10-25 明确选择由 GPT 仔细核对原文代替人工评阅。本轮按此要求推进，
参考与评阅均标记 assistant，不写为 human，也不将派生结果自动设为人工已确认。
GPT 参考答案须在提取模型处理独立留出材料前冻结；报告注明模型复核的局限。

风险：图表关系与科学支持无法由程序完全确认；长文有输入预算；选页直读不是整篇
原文覆盖。已有论文多为开发回归材料，不能再当新留出集。后续应增加跨领域、独立
专家复核样本，重新冻结规则及预算；当前GPT评阅不替代专家确认或复现实验验证。

### 后续证据复核与引用诊断

`EvidenceJudge`仍负责既有解析读法建议。原文对主张的支持检查复用通用extract任务，
不增加另一套引擎或自动认证状态。独立开发控制实验中，逐条复核能发现部分符号与
条件错误，但也会在解释承认对象不符时仍给出supported。因此仅提供任务示例，
不默认增加远程调用、不按判定自动改写旧结果。

旧运行诊断发现大量逐字引句填错相邻块ID。采用程序查找同篇当前材料中的精确
匹配位置，最多返回三个候选到已有的一次修复反馈；保留原候选和修复候选。
相比静默重定位、模糊匹配或放宽负号/下标校验，这个改动只增加可核查诊断。
不会跨文献、扩大已选页或改写解析工件，也不把匹配视为语义支持。
两篇旧候选的真实API对照复测中，剩余引用错误分别由6降至1、由8降至0；前者
仍失败，后者保存PARTIAL结果。这是小样本开发观察，不是科学正确率提升证明。

真实修订RS-20结果时发现：字段与主张可以修改，模型误写的“原文歧义”诊断却无法
用同一入口修正。扩展既有revise接口支持issue_index，仍只替换一个对象并保留
before与父结果，不引入单独的诊断管理系统。暂不删除/重排诊断，以保持历史索引
稳定；相关字段、主张和诊断分别修订，不作未经核对的连带修改。
修订增加可选authority来源（human/assistant），兼容旧人工记录；助手来源不能
设置confirm=true，修改已确认的内容会撤销相应确认。来源标记不是身份认证。

字段粒度开发实验没有支持自动拆分：条件关联错误仍存在，拆分还可能增加引文失败。
因此不增加任务拆分器或学科规则。实验另外发现，任务要求步骤为空时，模型仍生成
额外流程。对此增加可选的`include_steps`布尔配置，以JSON Schema的`maxItems: 0`
约束步骤及字段步骤引用，并由本地验证执行。相比删除额外步骤，这保留模型候选和
明确失败；相比按任务类型强制禁止，显式配置允许整理类任务按实际需要请求步骤。
省略时保持原行为，不改变旧结果验证；字段配置进入已有任务指纹，提示词仍为v8。
最终结构校验失败保持`invalid_model_output`类别，不再在批量清单中退化为泛化错误。

原文复核后的资料导出暴露一个展示缺口：字段 `context` 中的实验适用范围只保留在
JSONL，Markdown/CSV 读者看不到。现在直接复用已有字段：报告在值下显示说明，CSV
增加每字段 context 列，继续按普通文本转义和防公式注入。没有新结果格式、额外模型
调用或自动补写；旧结果可离线重导出。相比强迫模型把限定重复写到 value，这能保留
既有结构化语义，也避免新模型调用影响原结果。CSV 消费端应按列名读取。
