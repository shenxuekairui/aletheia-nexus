# Aletheia Nexus v0.7.1 发布说明

> **让论文不只停留在下载文件夹里，而是成为可以核验、整理和继续使用的科研资料。**

v0.7.1 延续 AN 的主线：从可信文献开始，逐步建立属于研究者和实验室自己的科研知识基础设施。它在 v0.7 的带来源解析与 AI 数据导出基础上，进一步连接文献获取、机构访问和本地整理，让这些能力成为一条更完整的日常工作流。

本文对应 `0.7.1`。正式发行记录见 [GitHub Releases](https://github.com/shenxuekairui/aletheia-nexus/releases)，可安装版本以 [PyPI](https://pypi.org/project/aletheia-nexus/)为准。此前版本和测试记录见[版本与验收记录](RELEASE_HISTORY.md)。

## AN 可以怎样帮助你

如果你需要收集一份文献清单、复用机构已有的访问权限、保存可追溯的本地资料，或为自己的检索与 AI 工作流准备数据，AN 提供以下流程：

1. **输入文献。** 使用 DOI、TXT 清单或 JSON/CSV 书目；知网也支持没有 DOI 的题名请求。
2. **合法获取并核验。** 查找公开来源或使用已授权接口与浏览器会话，确认拿到的是目标论文正文，而不是附件、登录页或另一篇文章。
3. **保存和整理。** 将 PDF 与来源记录保存到本地，按指定文件夹、名称和标签管理；批次可以核验后续跑。
4. **解析并回到原文。** 对已验证且具有真实 DOI 的论文提取结构，保留章节、页码、原文位置和处理状态；需要时使用可选 OCR。
5. **供后续工具使用。** 搜索解析结果，或导出 Markdown、JSONL 和带来源的结构化分块，交给你选择的模型、RAG 或工作流。

获取记录、原始 PDF、解析结果与导出内容各有职责。后续处理不应抹去原始证据，使用者也不必依赖某个模型平台才能保留自己的文献资产。

## 本版本的主要变化

### 更完整的文献入口

知网期刊论文接入统一获取流程，支持 DOI 和题名等书目信息。自动分流依据已有标识与元数据线索，不会把所有未成功的外文文献都转去知网。相似题名需要结合作者、年份等证据判断；无法确认的结果不会直接当作成功。

公开来源、其他出版社与知网共用正文身份和来源核验边界。不同访问方式的结果可以进入同一套本地工作流，不必为知网单独维护一套成功标准。

### 更自然的机构访问

可见浏览器默认采用普通启动方式，使用 AN 专用配置与直连网络，复用该配置中的机构会话。任务结束后保留浏览器窗口；继续运行时可以重用会话，而不影响日常浏览器配置。

已有机构 IP、校园网或 VPN 权限仍由网站判断。必须登录或完成验证码时，程序保留人工操作环节；AN 不代填凭据、不破解验证，也不承诺每个网站都接受自动化访问。需要托管浏览器生命周期时，仍可显式选择 `--browser-launch-mode managed`。

### 从保存文件到本地整理

输入中可以指定 `folder`、`filename` 和 `tags`。新文件默认使用 **年份-期刊-标题**，附加身份与内容短码以避免同名覆盖；信息不足时省略缺失字段，不编造元数据。

`library` 命令可以按文件夹、标签或关键词查看已有资料，也可以修改独立标签。管理基于本地文件与来源记录，不引入数据库或后台索引，不自动猜测分类，不修改原始 PDF 和获取证据。

### 更一致的可靠性边界

重复获取、断点续跑、本地管理、解析和导出都围绕已有证据检查文件。相同已验证文件再次获取时保留首次来源记录，续跑同时核对 PDF 与来源记录；不能确认的内容不会静默升级为成功。获取恢复也保持有界，不以反复刷新认证页面或放宽校验换取表面成功率。

## 开始使用

需要 Python 3.11+。安装命令获取的是 PyPI 上实际已发布的版本；请先用 `--version` 确认：

```bash
python -m pip install -U aletheia-nexus
aletheia-nexus --version
aletheia-nexus doctor
aletheia-nexus acquire 10.1371/journal.pone.0310216 --public-only --output-dir downloads/first-paper
```

需要浏览器机构访问时，另行安装可选依赖：

```bash
python -m pip install -U "aletheia-nexus[browser]"
python -m playwright install chromium
```

完整的输入、分类、解析和导出示例见 [README](../README.md#快速开始)；具体选项与故障处理见[使用说明书](USER_MANUAL.md)。

## 从 v0.7.0 升级时

- 既有 PDF 不会自动移动或批量重命名。新命名规则用于新保存的文件；备份或迁移时请一起保留来源、解析及标签等配套文件。
- 老检查点如果缺少来源记录哈希，将重新获取，而不是直接信任旧完成标记。重复取得相同已验证文件时保留首次获取证据；调整标签使用 `library tag`。
- 默认浏览器会在任务结束后保持打开，可手动关闭 AN 专用窗口；不要把它误认为未结束的下载。若要求程序管理关闭行为，可选托管启动模式。
- 继续使用 `parsed-document/v2` 解析契约。新获取能力不会放宽解析入口：仍要求已验证正文、真实 DOI 和匹配的文件及来源记录。

## 仍然明确的边界

AN 当前提供命令行工作流，不是图形文献管理器，也不内置自动研究 Agent。它不提供订阅权限，不绕过付费墙或验证码。

知网接入以期刊 PDF 为重点，不承诺全库覆盖，也不做 CAJ 转 PDF。没有 DOI 的论文可以在证据充分时获取并验证，但当前解析器仍要求真实 DOI；不会为此生成假 DOI。

`VERIFIED` 是文件身份与正文核验结果，不是对论文科学结论的认可。`PARSED` 也不表示理解了全部图表、公式和科学含义。OCR、复杂版式或证据不足导致的不完整结果会明确标注。科学语义抽取、知识图谱和更高层 Agent 仍是后续方向。

## 验证范围与发布状态

发布前的集成工作区已完成本地确定性回归、真实浏览器夹具、解析评测及安装包检查。测试覆盖获取、核验、本地整理、解析和导出；这些是工程回归证据，不是全出版社下载成功率或科学语义准确率。

正式发布以同一最终提交的云端 Python 3.11–3.14、Linux/Windows 浏览器、真实 OCR 和 clean-wheel 检查通过为前提；实际结果可在 [GitHub Actions](https://github.com/shenxuekairui/aletheia-nexus/actions) 按发布提交核对。详细数量、跳过原因与历史在线测试分别记录在[版本与验收记录](RELEASE_HISTORY.md)，不将本地检查或旧版本结果替代本版本最终发布验收。

AN 的方向没有改变：**先把可靠的科研对象、证据和工具做好，再让知识、工作流与智能体建立在它们之上。**
